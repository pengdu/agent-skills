# System Design Process

在设计完整系统、重构关键架构或进行系统设计评审时使用。不适用于只需单一组件配置或孤立技术问答的请求。

## 输入清单

- 用户、客户端和核心使用场景。
- 功能需求、非功能需求和明确不做的范围。
- 读写比例、峰值模型、数据规模、保留期和地域。
- 延迟、可用性、持久性、一致性和成本目标。
- 已有系统、依赖、合规与迁移约束。

## 六阶段流程

1. **需求边界**：列出主流程、边界条件、成功指标和非目标。
2. **容量估算**：估算 DAU/MAU、平均与峰值 QPS、读写比、存储、带宽和增长余量；说明假设。
3. **接口与数据**：定义关键 API、核心实体、访问模式、主键、索引和事务边界。
4. **高层架构**：从客户端、网关、服务、存储、缓存、异步链路到外部依赖描述关键数据流。
5. **瓶颈深挖**：选择最影响目标的两个问题，例如热点、并发竞争、索引新鲜度、连接规模或跨地域一致性。
6. **可靠性与演进**：给出降级、重试、幂等、监控、告警、容量阈值、迁移与分阶段演进方案。

## 决策规则

- 先以访问模式驱动存储和索引选择，再讨论具体产品。
- 写路径需要可靠异步传播时，定义事件契约、幂等键、重试和死信处理。
- 强一致只用于确实不能接受冲突的边界；其余部分明确可接受的陈旧度与补偿方式。
- 每一个缓存、队列、索引或副本都必须说明失效、重建和观测方式。

## 权衡与失败模式

- 低延迟读取通常以缓存陈旧和失效复杂度为代价。
- 高可用多副本通常以复制延迟、冲突处理或成本为代价。
- 异步化提高吞吐和隔离性，但引入重复、乱序、积压和最终一致性。
- 过早分片会增加运维复杂度；延后分片会增加热点和迁移风险。
