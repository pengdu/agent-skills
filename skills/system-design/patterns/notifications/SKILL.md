# Notification Service

## 触发条件与不适用场景

在请求涉及邮件、短信、Push、通知偏好、投递、提醒或告警时使用。不适用于仅在同步请求中返回一次性提示的请求。

## 输入清单

- 触发事件、目标用户、渠道、时效和送达要求。
- 用户偏好、免打扰、频控、去重窗口和敏感数据。
- 供应商 SLA、限流、失败重试和成本约束。

## 决策流程

1. 从业务事件异步触发通知，避免阻塞主事务。
2. 在编排层应用偏好、去重、频控和渠道选择。
3. 为每个渠道配置投递适配器、超时、重试和失效处理。
4. 记录投递状态、回执和失败原因，支持重放与审计。

## 权衡与失败模式

- 更积极重试提升送达率，但可能放大重复和供应商限流。
- 多渠道提升覆盖率，但增加偏好与一致性复杂度。
- 防止重复通知、失效 token、批量积压、供应商停摆和敏感信息泄露。
