# Third-party Integration

## 触发条件与不适用场景

在请求涉及支付网关、外部 API、Webhook、供应商限流或降级时使用。不适用于完全受本系统控制的内部同步 RPC。

## 输入清单

- 外部 API SLA、认证、配额、超时和回调模型。
- 写操作副作用、失败成本、对账和替代供应商。
- 重试预算、幂等键、签名验证和审计需求。

## 决策流程

1. 为调用定义超时、重试预算、指数退避、熔断和降级。
2. 所有外部写操作携带稳定幂等键，并持久化请求状态。
3. Webhook 先验签、去重、持久化，再异步处理状态机。
4. 用对账任务修复异步状态差异，并保留供应商事件审计。

## 权衡与失败模式

- 重试提高临时故障恢复率，但会造成重复副作用，必须幂等。
- 同步等待响应简单，但将供应商抖动传播给用户路径。
- 防止级联超时、重复收费、回调乱序、供应商停摆和限流。
