# Feed Fan-out

## 触发条件与不适用场景

在请求涉及动态流、关注关系、时间线、粉丝分布、读扩散或写扩散时使用。不适用于单一资源详情页读取。

## 输入清单

- 作者粉丝分布、发帖频率、读写比和时间线延迟。
- 新鲜度、排序、删除、隐私和回填需求。
- 存储规模、热点作者阈值和成本目标。

## 决策流程

1. 普通作者使用写扩散，提前写入关注者候选时间线。
2. 超大作者使用读扩散，在读取时合并其内容，避免写放大。
3. 混合模式按粉丝阈值路由，并使用游标分页与去重。
4. 删除、隐私变更和回填通过事件传播并保留可重算来源数据。

## 权衡与失败模式

- 写扩散降低读延迟但大 V 会导致写放大。
- 读扩散降低发布成本但增加读时合并和尾延迟。
- 防止时间线陈旧、重复条目、删除传播遗漏、热点作者压垮扇出和回填成本失控。
