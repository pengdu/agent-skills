# Distributed Concurrency

## 触发条件与不适用场景

在请求涉及库存、票务、座位、限量资源、预留、超卖、锁或幂等时使用。不适用于可接受无冲突覆盖的低竞争更新。

## 输入清单

- 竞争资源、峰值并发、预留时长和可接受超卖。
- 确认、支付、取消与超时流程。
- 原子更新能力、事务范围、时钟和审计要求。
- 客户端重试、重复请求与故障恢复路径。

## 决策流程

1. 先定义资源状态机，例如可用、预留、确认、释放、过期。
2. 优先使用数据库条件更新或事务保证库存扣减原子性。
3. 跨服务竞争时才使用带租约和 fencing token 的分布式锁。
4. 所有创建、支付确认和释放请求使用幂等键；预留以服务端到期任务释放。

## 权衡与失败模式

- 悲观锁降低超卖风险但降低吞吐；乐观条件更新在冲突可重试时更易扩展。
- 租约锁不能单独防止失效持有者写入，需 fencing token 或版本检查。
- 防止时钟偏差、重复扣减、锁失效后写入、支付成功而预留失效、死锁和过期任务漏执行。
