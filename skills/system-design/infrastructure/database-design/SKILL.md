# Database Design

## 触发条件与不适用场景

在请求涉及 schema、表、文档、主键、索引、复制、分区、分片或事务时使用。不适用于只讨论缓存键或纯全文检索索引的请求。

## 输入清单

- 实体关系、读写路径、查询条件和排序要求。
- 事务边界、冲突容忍度、延迟和持久性目标。
- 数据规模、增长、保留期、热点和地域分布。
- 迁移限制、审计和合规要求。

## 决策流程

1. 从访问模式反推表/集合、主键、排序键和二级索引。
2. 强事务与复杂关联优先关系型数据库；按主键高扩展的聚合读取可选宽列或文档数据库。
3. 读取扩展使用读副本；写入扩展使用分区或分片，并避免低基数字段做分区键。
4. 明确主副本、复制延迟、读一致性和 schema 演进策略。

## 权衡与失败模式

- 读副本提高读取吞吐，但可能读到旧数据。
- 分片扩展写入，但增加跨分片查询与事务复杂度。
- 二级索引简化查询，但增加写放大和重建成本。
- 防止热点分区、跨分片事务失控、复制延迟、索引膨胀和不可逆 schema 变更。
