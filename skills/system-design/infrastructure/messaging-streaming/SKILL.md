# Messaging and Streaming

## 触发条件与不适用场景

在请求涉及异步任务、事件驱动、Kafka、队列、CDC、消费者或实时聚合时使用。不适用于必须同步完成且没有异步传播需求的简单内部调用。

## 输入清单

- 事件速率、峰值、顺序范围、保留期和回放需求。
- 可接受重复、丢失、延迟与消费者数量。
- 生产者事务边界、事件 schema 和下游副作用。
- 消费延迟、失败重试、审计和运维目标。

## 决策流程

1. 高吞吐、可回放事件日志选择 Kafka 类平台。
2. 独立工作分发选择队列；数据库变更传播选择 CDC；实时聚合使用流处理。
3. 以业务键作为分区键，并明确其顺序保证范围。
4. 定义至少一次投递下的幂等消费者、重试、DLQ 和回放策略。

## 权衡与失败模式

- 异步化提升吞吐和隔离，但增加最终一致与排障成本。
- 更细分区提高并行度，但削弱跨分区顺序。
- 防止重复投递、乱序、毒消息、消息积压、消费者滞后和 schema 不兼容。
