# Geospatial Design

## 触发条件与不适用场景

在请求涉及附近、经纬度、位置更新、地图渲染、路线或 ETA 时使用。不适用于只按城市 ID 或普通文本地址过滤的请求。

## 输入清单

- 查询类型：附近检索、实时位置、地图展示或路径规划。
- 搜索半径、精度、更新频率、区域规模和热点分布。
- 数据陈旧容忍度、路线时延和交通数据要求。
- 客户端渲染、离线、成本和全球覆盖约束。

## 决策流程

1. 附近查询使用 Geohash、Quadtree 或 S2，并设计边界邻格扩展。
2. 高更新频率的实时位置按空间单元和时间窗口写入。
3. 地图展示使用分层瓦片与 CDN。
4. 路径规划使用图搜索、分层路网或预计算；不要把路径规划简化为 Geohash 查询。

## 权衡与失败模式

- Geohash 简单但边界查询需要邻格补齐；S2/Quadtree 更灵活但实现和运维更复杂。
- 更高精度增加索引、写入和查询成本。
- 防止格网边界漏查、热区倾斜、位置陈旧、极区变形和路线重算过载。
