# Realtime Communication

## 触发条件与不适用场景

在请求涉及聊天、实时状态、协作、在线推送、长连接或低延迟双向通信时使用。不适用于仅需定时批处理通知的请求。

## 输入清单

- 并发连接、消息速率、时延与地域目标。
- 双向交互、在线状态、离线补偿与重连需求。
- 顺序、去重、确认与持久化保证。
- 心跳、连接迁移、慢客户端和容量限制。

## 决策流程

1. 双向低延迟交互使用 WebSocket；受限环境或轻量通知可使用长轮询。
2. 将连接注册到可查询的路由层；跨节点投递经 Pub/Sub 或消息总线。
3. 在线消息与持久化消息分离；离线客户端通过游标补拉。
4. 定义心跳、断线重连、确认、幂等消息 ID 和每会话顺序范围。

## 权衡与失败模式

- 长连接降低交互延迟，但增加连接状态和容量管理。
- 全局强顺序成本高，通常限制在单会话或单分区。
- 防止连接迁移丢路由、慢客户端阻塞、重复/乱序、心跳风暴和重连风暴。
